# Test — v0.2 reactions, receipts and sending limits (2026-11-13)

Same setup as the [v0.1 end-to-end test](2026-11-10-e2e-v0.1.md): Linux server with Docker,
one instance linked to a real personal number, a receiver that checks signatures and logs only
metadata. Messages were sent to the number's own chat ("Message yourself").

## Results

| Area | Result |
|---|---|
| Build and restart with `0.2.0-dev` | OK — session restored by itself, no new pairing |
| `POST /messages/reaction` (👍 on our own message, `fromMe: true`) | OK — 200 with the reaction message id, shown on the phone |
| Reaction with text instead of an emoji | OK — 400 `invalid reaction: emoji must be a single emoji …` |
| Reaction in a group without `participant` | OK — 400, nothing sent |
| Reaction with an invalid `messageId` | OK — 400, nothing sent |
| `GET /instances/{id}` → `sending` | OK — `lastMinute`/`lastHour` count every kind of message (text and reaction) |
| `message.status` | OK — `delivered` and `read` keep arriving after the change |
| Sending limit (`SEND_MAX_PER_HOUR=1`, temporary) | OK — 1st message 200; 2nd **429 in 1.5 ms** with `Retry-After: 3600` and `retryAfter` in the body; the 2nd message never reached WhatsApp |
| Back to the default limits | OK — counters reset on restart, instance connected |

## Not covered yet

- `played` receipts and group receipts with `participant`: implemented, waiting for a voice
  note sent from the API to be played, and for a group message read by someone.
- A received reaction with `target`: the classification is covered by unit tests
  (`TestDescribeReaction`); waiting for someone to react to a message on the phone.
- Media download (`POST /media/download`) against a real received file: waiting for a photo
  and a voice note sent to the number's own chat.
- Queue order under concurrent requests: the queue is a channel of capacity 1 (first come,
  first served); a load test is planned before v1.0.

## Replies, edits and deletes (same day, later)

| Area | Result |
|---|---|
| Text with `replyTo` (quoting our own message, with `text`) | OK — 200, message id returned |
| `POST /messages/edit` on that reply | OK — 200 |
| `POST /messages/delete` of our own message (`fromMe: true`) | OK — 200 |
| Delete someone else's message in a private chat | OK — 400, nothing sent |
| Edit with blank text | OK — 400, nothing sent |
| `replyTo` in a group without `participant` | OK — 400, nothing sent |
| Sending counters | OK — replies, edits and deletes counted like any message (5 in the minute) |

Checked on the phone (WhatsApp Desktop): the reply shows the quote bubble with the original
text, the edited reply shows the "Edited" label and the new text, and the deleted message shows
"This message was deleted".
